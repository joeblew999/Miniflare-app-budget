# CLAUDE.md

Conventions for working in this repo (Baht & Dollar Budget on Cloudflare Workers).

## Three files, three jobs

| File | Holds | Never holds |
|---|---|---|
| `mise.toml` | Tool versions only (`[tools]`: node, fnox) | Tasks, env vars, secrets |
| `package.json` | Every command, as `noun:verb` npm scripts that call `cli/` | Secrets, logic |
| `fnox.toml` | Names of secrets and env vars the project needs | Secret values |

- Each person keeps their own secret values in their own store (keychain, 1Password, age…), wired up in `fnox.local.toml`, which is gitignored. Never commit a value.
- A command that needs secrets runs them through `fnox exec -- …` inside its npm script, e.g. `worker:deploy`.
- Do not add `[tasks]` or `[env]` to `mise.toml`, and do not add `.env` files.

## Commands: noun:verb

Every command is a subcommand of the project CLI, a TypeScript program in `cli/`. Node 22 runs it
directly (type stripping), so it has no build step and no tsx. Each one is exposed as an npm script
named `noun:verb` that calls `node cli/main.ts <noun> <verb>`. The noun is the thing being acted on,
like a tag. Use the existing nouns before inventing a new one.

| Noun | Scripts | What it acts on |
|---|---|---|
| `app` | `app:dev`, `app:check`, `app:build`, `app:preview`, `app:lint` | The whole app: React front end and Worker, built together by Vite |
| `worker` | `worker:types`, `worker:deploy` | The Cloudflare Worker (wrangler) |
| `ui` | `ui:add` | shadcn components in `src/components/ui/` |
| `theme` | `theme:show`, `theme:set`, `theme:gen` | The shadcn preset and accent themes |
| `env` | `env:list`, `env:check` | Secrets and env vars (fnox) |

Rules:
- No `scripts/` folder and no loose `.js`/`.mjs` tooling. Tooling is a command in `cli/commands/<noun>.ts`, registered in `cli/main.ts`.
- No bare script names (`dev`, `build`, `start`). Always `noun:verb`, and the npm script must match the CLI path (`app:build` → `cli/main.ts app build`).
- Reuse short verbs across nouns: `dev`, `check`, `build`, `preview`, `lint`, `types`, `deploy`, `add`, `show`, `set`, `gen`, `list`, `check`.
- A new command goes in this table and in the README in the same change.
- Pass arguments after `--`, e.g. `npm run ui:add -- dialog`, `npm run theme:set -- b2oDXH5AO`. `npm run cli -- --help` lists everything.

## Folder layout

```
cli/            project CLI (TypeScript, commander): main.ts, run.ts, commands/<noun>.ts
src/            React app (Vite + shadcn)
  components/       app components; components/ui/ is managed by the shadcn CLI
  lib/              front-end helpers (theme.ts, storage.ts, utils.ts)
  styles/           index.css (base preset), themes.css + themes.json (generated)
worker/         Cloudflare Worker entry. /api/* goes here; everything else is static assets
shared/         code used by both src/ and worker/ (domain model; the oRPC contract goes here)
public/         static files copied as-is
```

- `shared/` must stay runtime-neutral, with no DOM, no `localStorage` and no Worker bindings. The type-check enforces this, because `shared/` is compiled under both the app and the Worker tsconfigs.
- TypeScript is strict everywhere, with one tsconfig per runtime: `tsconfig.app.json` (src + shared, DOM), `tsconfig.worker.json` (worker + shared, Workers types from `worker-configuration.d.ts`), and `tsconfig.node.json` (vite.config + cli, Node). `npm run app:check` checks all three.
- `worker-configuration.d.ts` is generated by `npm run worker:types`. Re-run it after changing `wrangler.jsonc`.

## Theme (shadcn)

- The base theme is an official shadcn preset (see `theme:show`). Change it with `theme:set`. Never hand-edit colour variables in `src/styles/index.css`.
- `src/styles/themes.css` and `src/styles/themes.json` are generated by `theme:gen` (one block per official accent theme, built by running `shadcn init --preset` for each). Don't edit them by hand. Re-run `theme:gen` after `theme:set`.
- Runtime switching (light/dark/system plus accent) lives in `src/lib/theme.ts` and `src/components/theme-switcher.tsx`, and uses `.dark` and `<html data-accent="…">`. The boot script in `index.html` mirrors `applyTheme()` so there's no flash. Keep the two in step.
- `src/components/ui/` is managed by the shadcn CLI (`ui:add`, `theme:set`). Put app-specific components in `src/components/`.

## Git

- Work on a branch and open a PR. Never push to `main`. Keep the PR mergeable, because the owner's local clone tracks the same code.
- Run `npm run app:build` (type-check and build) before pushing.
