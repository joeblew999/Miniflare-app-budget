# CLAUDE.md

Rules for working in this repo: Baht & Dollar Budget, a contract-first app on Cloudflare Workers. Only rules live here.
What each command does is in [docs/commands.md](docs/commands.md), generated from the CLI, and how each part works is in
the comment at the top of its file. Don't repeat either here.

@docs/commands.md

## Stack

oRPC v2 (beta) contract with Zod 4 · Cloudflare Worker + D1 (Drizzle) · Better Auth · React 19, Vite, Tailwind v4,
shadcn/ui, TanStack Query · Vitest in workerd · a TypeScript CLI in `cli/` that Node runs directly. Versions are in
`package.json` and `mise.toml`.

**oRPC is v2 beta. What models learned about oRPC is v1 and wrong for v2.** Before changing the contract, the router or
the client, load the vendored skills in `.claude/skills/` (`orpc`, `orpc-contract`, `orpc-openapi`). Keep every
`@orpc/*` package on the same exact version.

## One source for each thing

- `mise.toml`: tool versions only. No `[tasks]`, no `[env]`.
- `package.json`: the goals (`noun:verb` scripts) and the order of steps (Wireit `dependencies`, `files`). No secrets, no code.
- `fnox.toml`: names of secrets and env vars, never values. Each person's values live in their own store, referenced from
  the gitignored `fnox.local.toml`, which `env:setup` writes. No `.env` or `.dev.vars` files.
- `docs/commands.md`: the only list of commands, generated by `docs:gen`. Never list commands by hand; link to it.
- A list the code needs, like a token's permissions, exists once in the code, and everything else is derived from it.

## Commands

- Every command is a subcommand of the CLI in `cli/commands/<noun>.ts`, registered in `cli/program.ts`. Everything a
  command does lives in its noun's file; code shared by more than one noun goes in `cli/lib/`. Nothing else goes in `cli/`.
- Every CLI command is a Wireit goal (`scripts` and `wireit`) or a step (`wireit` only), named after it (`app:build` runs
  `node cli/main.ts app build`), and `package.json` lists them in the CLI's order. `app:lint` fails if they don't line up.
- A command does one thing and never calls another command. What it needs first goes in its Wireit `dependencies`.
  Never write "run X, then Y" in docs or code.
- Give a step `files` (and `"output": []` if it writes nothing) so Wireit skips it when nothing changed.
- Use the nouns and verbs already in docs/commands.md before inventing new ones.
- A command that needs a person (a dashboard form) never waits: it opens what's needed, says what to do and stops; the
  next run carries on from there.
- Pass arguments after `--`. Every command prints timings to stderr; `BUDGET_TIMINGS=0` hides them.

## Code

- The contract in `shared/contract.ts` is the source of truth. Every procedure has `.output` and an `openapi()` route;
  procedures that need a user use `authed`, and every query filters by `context.user.id`.
- `shared/` stays runtime-neutral: no DOM, no Worker bindings, no Node APIs. The type-check enforces it.
- Database changes: edit `worker/db/schema.ts`, then `db:gen`. Never edit an applied migration. Migrations must work with
  the code that's still running: add columns and tables first, remove old ones in a later release.
- Generated, never edited by hand: `src/components/ui/` (shadcn), `src/styles/themes.css` and `themes.json`
  (`theme:set`), colour variables in `src/styles/index.css`, `worker-configuration.d.ts`, `docs/commands.md`.
- Change together: the theme boot script in `index.html` and `applyTheme()` in `src/lib/theme.ts`; for offline use,
  `vite.config.ts`, `src/App.tsx`, `src/hooks/use-budget.ts` and `src/lib/storage.ts`.
- `artifact/` is glue only; app and API changes go in `src/`, `shared/` and `worker/`.
- Plans are GitHub issues labelled `plan`, with their steps as checkboxes. PRs that carry them out say `Closes #N` or `Part of #N`.

## Cloudflare

- Deploying is a git push: `main` is production, and every other branch gets its own Preview on a staging database.
- Never set Cloudflare up by hand. Anything missing goes into `worker:setup` or `env:setup`, so it stays repeatable. The
  only manual steps are creating tokens in the forms `env:setup` opens.
- Guest sign-in (`GUEST_SIGN_IN`) is never `"true"` in production.
- `wrangler.jsonc` holds no account-specific ids except the staging database's; keep its two entries in step.
- Agents (cloud sessions) get Cloudflare access with `env:lease`, never by asking for a token. They deploy their branch's
  Preview with `worker:preview`, never production.
- After a push, check the deployed copy with `app:smoke`.
- Whenever a Preview is deployed, give its URL (`https://<branch>-baht-dollar-budget.gedw99.workers.dev`) and its API
  docs (the same URL plus `/api/docs`) first in the reply to the person, and in the PR description.

## Git

- Work on a branch and open a PR; never push to `main`. Keep the PR mergeable.
- Before pushing, run `npm run app:verify`.
